## What we do

Flintwillow Software builds open source software with a focus on **data ownership** — software
you run, on hardware you control, where your data stays yours. We prefer self-hosted over
SaaS, plain files over proprietary formats, and tools that keep working when a vendor
disappears.

That principle shapes everything here: composable services, explicit infrastructure as code,
and no lock-in by design.

## Contributing

All public repositories use our shared
[**repo-template**](https://github.com/flintwillow-software/repo-template) conventions, and
issue and pull request templates are provided organization-wide via
[**.github**](https://github.com/flintwillow-software/.github).

Before opening a PR, please:

1. Check for an existing issue, or open one using the appropriate template
   (🐛 Bug Report, ✨ Feature Request, 📐 Epic, or 📋 Task).
2. Work on a feature branch — never commit directly to the default branch.
3. Use [Conventional Commits](https://www.conventionalcommits.org/) for your commit messages.

## Contact

- **Issues & feature requests** — please open an issue in the relevant repository;
  we'd rather track it in public than in a private inbox.
- **Security disclosures** — do **not** open a public issue. See the `SECURITY.md`
  in the affected repository, or contact us directly.
- **Everything else** — reach the maintainers via
  [GitHub Discussions](https://github.com/orgs/flintwillow-software/discussions)
  on the relevant repo.
